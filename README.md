# NIRIA

一位长期伴侣，一起积累的生活。NIRIA 首先在 Windows 上提供日常聊天、持续的人格与记忆，以及可选的主动关心。模型、图片编辑、朗读、同步服务由用户自行选择。

当前源码版本为 **0.31.0 开发预览**：已实现 Electron 桌面窗口、伴侣小窗、窗口偏好恢复、SQLite 实体表保存与旧库迁移、同步元数据按记录写入、聊天与等待回复期间的草稿保护、成功后再替换原回复的重生成、随资料和期限变化重新核对的发送范围、历史分页与本地文字搜索、记忆分页与组合筛选、带来源的记忆管理、记忆纠正与旧来源阻止、记忆期限编辑及遗忘清单、随记忆变化维护的本机话题检索索引、主动问候、聊天驱动表情、透明动作帧混合、可恢复的本机纯色背景处理、图片基础检查与本机位置修正、独立朗读、加密 WebDAV 同步、同步换钥与中断恢复，以及完整资料的加密备份。Windows 桌面版可选择用系统加密记住服务配置及配对码。同步已用本机独立客户端及真实 HTTP 测试服务器验证，尚未用实际 Nextcloud 和两台实体 Windows 完成验收。真实形象生成质量仍待实测，首版需求尚未全部交付。

## 在 Windows 上运行

最近构建并验证的本机包为 **0.30.0 开发预览**：`release/NIRIA Setup 0.30.0.exe`；可直接运行的目录版为 `release/win-unpacked/NIRIA.exe`。111 个运行文件与当时的 0.30.0 受测源码逐字节一致，尚未包含 0.31.0 的引用保护；安装后的完整回归、发送范围与实际记忆选取、窗口恢复、备份界面检查、损坏凭据文件下的实际启动/重启及 0.7.0/0.14.0 旧库升级均通过。包内真实 Haru 模型的双窗口播放、备份/本机 WebDAV 恢复与重启也通过。安装器及原生卸载器 CRC 已核对，当前用户、中文及空格路径下的实际 0.14→0.30 覆盖升级、卸载保留、重装恢复和最终清理全 11 阶段通过。安装器中的应用归档、可执行文件及运行时许可与受测目录版相同，旁附 `.sha256`。原 0.28.0/0.29.0 包及其证据保留。此本机包包含单独取得的 Live2D SDK，仅用于本机开发验证；没有代码签名、上传或公开发布。

从源码运行需要 Node.js 22.13 或更高版本（当前验证为 Node.js 26）：

```powershell
npm ci
npm run desktop
```

0.30.0 不带可选 Live2D SDK 的隔离源码副本已从锁文件重新安装独立依赖，通过 Node 测试、完整伴侣浏览器流程及 Electron 桌面回归。缺少 SDK 时保留聊天和单图功能，模型播放及采用会明确停用。本轮使用已有 npm/Electron 缓存离线安装，没有复用主工作区的依赖目录；锁文件中 27 个 esbuild 镜像地址已统一为 npm 官方仓库，依赖版本和完整性摘要不变。首次安装依赖及准备 Electron 在缺少缓存时可能联网，本轮没有验证空缓存的在线安装。详细范围及首次桌面焦点检查的失败/重跑记录见 [配置与兼容清单](docs/compatibility.md)。

主窗口右上角可打开伴侣小窗，拖动小窗顶部可移动位置，使用 `−` 收起、`+` 展开，点击形象或消息返回聊天。小窗“置顶”按钮和托盘“伴侣始终置顶”控制小窗是否保持在其他窗口上方。显示小窗时保留当前聊天焦点；聊天窗口最小化后可从小窗或托盘恢复。

应用会记住主窗口的位置、大小和最大化状态，以及小窗的位置、显示、收起和置顶状态。点击小窗 `×` 或按 Alt+F4 会隐藏小窗，下次启动继续保持隐藏。托盘“找回伴侣小窗”将小窗移到鼠标所在屏幕的右下角；启动和显示器范围变化时也会修正屏幕外的位置。关闭主窗口会退出整个应用并停止主动关心。

窗口偏好保存在桌面资料目录的 `desktop.json`，只影响这台电脑，不进入伴侣备份或同步。偏好损坏时使用默认布局并提示；读取到较新版本的格式时保留原文件，本次布局修改仅在当前进程生效。

也可以仅运行本地浏览器预览；这一模式不需要安装第三方依赖：

```powershell
npm start
```

打开 `http://127.0.0.1:4217`。`NIRIA_PORT` 可改变端口。浏览器预览的资料默认在项目的 `.niria/companion.sqlite`，桌面版默认在 Windows 的 `%APPDATA%\niria` 或 `%APPDATA%\NIRIA` 资料目录。两个模式默认使用不同资料，可用加密备份转移。

从 0.8.0 起，应用会将旧的单行快照自动迁移为实体表。0.15.0 进一步将整段同步元数据拆成独立记录，保存到存储版本 3，保留身份、来源、权限、删除标记、形象和同步版本关系；失败时回滚，不新建空白伴侣。迁移后的资料库拒绝 0.14.0 及更早版本直接读取。升级前可在旧版保留完整加密备份及配对码；新版本仍支持恢复 v1 备份，远端同步协议与配对码不变。详见 [本机存储与升级](docs/storage.md)。

## 开始相处

1. 打开设置，填写对话 API 根地址、模型和密钥。首个适配器使用基础 Chat Completions，向根地址后的 `/chat/completions` 发送请求；本机免密服务可以不填密钥。
2. 应用连接不会调用服务。“测试连接”发起一次真实请求。默认仅本次进程使用；Windows 桌面版可勾选“在此电脑安全记住配置”，下次启动恢复连接。
3. 在“伴侣资料”设置名字、你希望的称呼、性格、说话方式和目前关系。自动记忆不会改写这些核心设定。
4. 开始聊天。角色和消息保存在本机，更换模型不会改变伴侣身份。“发送范围”可查看下一次请求引用的资料；回复下方可以查看实际引用过的记忆。
5. 在“记忆”中查看自动整理的待确认条目，确认、编辑、设置权限或删除。来源改变的条目立即停用。删除记忆会阻止从相同来源自动重建；“忘记相关记录”先展示影响清单，确认后删除来源、关联回复和依赖这些记录的衍生记忆。
6. 在“记忆与关心”配置自动记忆的每日请求上限、模型与同步权限，以及主动关心。主动关心默认关闭，仅在应用运行且配置了模型时执行，不补发错过的问候。

普通聊天每次 1 次模型请求；自动整理默认开启，每次成功聊天最多再请求 1 次，每天默认最多 8 次。整理只发送刚刚的用户消息，最多产生三条待确认记忆。失败不自动重试。主动关心、记忆整理、连接测试的实际请求均列在“备份与调用”中，失败和未知结果也计入每日上限。

等待回复时可以继续输入。回复成功只清除自发送后没有修改过的原草稿；失败保留输入，手动重新回复也保留正在编辑的草稿，不新增一条用户消息。

“重新回复”在等待期间保留原回复及其记忆，界面说明成功后才替换。重生成请求排除原回复与依赖它的记忆；成功时在同一事务中替换旧回复并停用相关记忆。失败、停止、超时或本机保存失败会保留原内容，不自动重试。等待时修改最近消息、改变原回复或执行遗忘，会拒绝过时的替换结果，继续保留用户的新操作。

所有对话服务请求在提交前先保存调用记录及使用量。初始记录失败不会请求模型；结果记录失败会尽可能保存“结果未知”，不会据此交付未能确认保存的替换回复。取消、超时仍可能已计费，迟到内容不进入聊天；恢复备份前的旧结果也不会写入恢复后的资料。“测试连接”页面断开会取消自己的请求。后台整理失败或记录失败不撤销已完成的文字回复，也不自动重复调用。

聊天窗口默认读取最近 120 条未删除记录。点击“回顾聊天”可以每页 60 条向前、向后浏览，输入聊天中出现过的文字进行本地搜索；中文按原文字串匹配，英文 ASCII 不区分大小写，百分号等符号按普通文字处理。点击“查看前后聊天”回到该条消息附近，并清除搜索条件。历史日期包含年份，较早消息可删除，编辑和重新回复仍仅开放给全局最近一条用户消息。

历史搜索不调用模型，也不会把搜索词存进伴侣资料或发送给服务。聊天发生编辑、删除、同步或恢复后，打开的历史页会重新定位，旧请求晚返回也不会覆盖新搜索。记忆来源在展开时单独读取，并核对当前修订和正文哈希，不受最近 120 条显示范围限制；来源已改变时不显示旧正文。

记忆页每次读取最多 60 条，可双向翻页，并组合本机文字搜索、类型及“待确认”“已确认且有效”“停用、过期或冲突”筛选。较早页编辑后保留当前页的位置，锚点删除或不再匹配时回到最近记录；离开记忆页清空当前结果。筛选不调用模型，也不写入伴侣资料。主窗口与小窗刷新只读取记忆摘要，不反复传输完整列表。

回复下的“引用的记忆”按需核对当时的引用，较早的记忆同样可查看；记录改变、到期或删除后不显示旧正文。查看期间期限到达会先清除内容，再重新核对；已在传输期间到期的结果不会显示。关闭弹窗后取消读取并清除结果，迟到响应不会再次打开弹窗。

当前上下文选取最多 24 条近期有效消息及最多 30 条有效记忆，并分别设置文本总量上限。记忆先按当前消息中的词语召回，再补充已确认与近期资料；支持中文分词、复合词片段和英文大小写/全半角归一化。检索只在本地执行，不额外请求模型；它是词语相关性检索，尚无 embedding 或深层语义召回。

来源检查每轮复用消息索引；0.21.0 使用进程内倒排索引匹配话题，新增聊天或保存调用记录会保留未变记忆的分词。纠正、失效、撤权和删除会清除旧词条，新增及修改的正文在下次检索时才分词；恢复、同步替换快照和事务失败会丢弃原索引并按有效资料重建。索引不写入数据库、备份或同步。伴侣实体表与同步元数据只写入发生变化的记录，不重写其中未修改的形象和历史消息。窗口读取最近记录、SQL 历史及记忆分页已经实现；应用核心仍全量载入和比较内存状态及同步修订图，单个实体的修订图仍整条保存，远端也仍整包上传。

发送前的“发送范围”按输入框草稿预览相关资料，并标记“话题相关”“已确认资料”或“近期线索”。非空草稿按实际发送时占用一条消息及相应字数，预览与发送共用选取逻辑。修改输入、资料、记忆、权限或对话连接时，打开的预览会清除旧结果并重新核对，也可以点击“重新核对”；核对只在本机执行，不调用模型。预览反映核对时的状态，真正发送仍会按当时的资料重新选取。

模型回复保留实际引用来源。禁止向模型发送的记忆、已删除、已过期、失效或存在冲突的记忆不会进入检索；被禁止记忆的来源与关联回复也从上下文排除。

“编辑”可修改正文、记忆类型与适用期限，添加手动记忆也可设置。只改类型或期限会保留原来的来源、待确认状态和停用状态；改动正文会成为你手动确认的独立资料。时间按本机时区输入，保存为统一时间；到期后停止引用，原记录仍可查看并调整期限。设为“长期保留”移除期限，不会复活已失效的来源。表单打开后若收到其他版本，保存会拒绝覆盖，需重新查看。

从 0.11.0 起，纠正正文仍保留原消息的编号、修订和正文哈希，不复制旧正文。纠正前的来源版本及其回复链退出模型上下文，依赖这些记录的其他记忆保守停用，旧来源不能再次自动整理；原聊天仍能在本机查看。相同消息后来修改的版本，以及新发送的消息，可以提供新资料。纠正后的记忆不依赖原消息继续有效，原消息普通删除或改写不会使你的纠正失效。

纠正条目可以展开“原关联记录”，模型与同步权限仍覆盖这些关联和回复。“忘记相关记录”也会列出并删除关联的纠正条目；单独删除记忆保留原聊天和版本阻止标记。纠正本身到期或被删除后，旧来源版本不会因此重新参与模型上下文。相同伴侣恢复纠正前的旧备份时，会保留本机已有纠正及必要的同步版本关系；备份本身已有纠正版本时采用备份正文，合并原关联记录。

这套规则依赖记录的来源关系，不判断其他独立消息在语义上是否矛盾；同来源中其他有效事实可手动重写或添加为独立资料。0.10.0 及更早版本已丢弃的纠正来源无法自动找回，旧客户端也不会执行新的阻止规则。备份和同步格式仍为 v1，使用这项能力的设备需运行 0.11.0 或更高版本。

“忘记相关记录”列出将删除的记忆、来源消息与关联回复，清单可继续展开，也可以查看完整聊天后取消。它依据已记录的来源 ID 和回复关系计算，包含相关冲突版本，不根据文字相似性扩大范围。新的衍生资料或相关正文变化会使旧清单失效，需重新查看后确认；预览、取消及执行不调用模型。

0.10.0 修正了此前回复衍生记忆只停用、仍保留正文的遗漏。现在本机、旧备份恢复、同步及换钥合并共用同一套关系传播；即使来源已在本机删除，仍保留遗忘标记，其他端相关记录到达时继续处理。重新打开旧资料时也会按已有标记补齐遗漏的衍生删除并清理当前同步正文。独立消息以及没有记录来源关系的手动资料不因此删除；旧磁盘页、备份和服务端历史副本不承诺擦除。

## 在此电脑记住配置

Windows 桌面版的对话、图片、朗读与 WebDAV 连接可分别选择“记住”；配对码有独立的保存开关。使用 Electron `safeStorage` 异步接口调用 Windows 系统加密，密文写入资料目录中的独立 `credentials.sqlite`，不写入普通伴侣资料、备份或同步对象。

保存后重启可恢复连接，不会仅因读取配置而测试或调用模型。保存的朗读或自动同步选项会随连接恢复；配对码另需勾选保存，才能自动解锁。系统保护不可用或资料解锁失败时，不降级为明文保存，仍可重新填写并只在本次使用。浏览器预览不提供持久保存密钥。

密钥输入框不会回显现有密钥。“留空时继续使用当前密钥”只允许同一 API 根地址；WebDAV 还要求账号相同。更换地址时应重新填写，或取消保留以连接免密服务。图片编辑请求绑定确认时的配置，另一窗口更换服务后旧确认不能直接上传到新服务。

在“备份与调用”可清除本机已保存配置，当前会话仍可继续使用；“锁定并断开”会删除保存的配对码、清除同步内存连接，使下次启动保持锁定。此操作不会撤销第三方服务器上的访问密钥。

Windows 系统加密用于保护此设备落盘的服务配置，不是跨设备恢复方式，也不表示普通聊天数据库已加密。新电脑使用伴侣备份恢复后仍需重新配置服务。

## 一张图片与可动形象

首页可以直接导入 PNG、JPG、WebP 单人图片，或导入形象实验台导出的素材包。图片和已保存动作会随伴侣持久保存。

打开左侧“形象”，进入实验台：

1. 导入一张清晰的二次元单人立绘，最大 8 MB、2000 万像素。原图在本机等比适配到 1024 × 1536，多余区域留透明边。已有伴侣形象会自动载入，无需再次导入。
2. 如果立绘带近似纯色背景，可先点击“预览透明背景”，逐张检查原图和已有动作，确认后采用；不调用图片服务。随时可“恢复原背景”，保存后主窗口与小窗一同生效。复杂背景仍需其他方法处理。
3. 单独配置图片编辑服务的 API 根地址、模型和密钥。
4. 为闭眼、微笑、疑惑或害羞选择“生成”，确认本次 1 次图片编辑请求后才会上传参考图。
5. 比较原图，按需使用“叠加原图对照”。找到可靠的小幅位置差异时会提供本机对齐预览，可取消对齐查看服务返回的位置。选择采用或放弃，单个动作可以重做。
6. 点击“保存到伴侣”保留原图和采用的动作，点击左上角 NIRIA 返回聊天。叠加对照不会保存成动作图，重开实验台可继续使用已保存素材。

保存期间按钮会暂时禁用。若伴侣或形象已在别处改变，页面会保留当前编辑内容并提示导出，保存按钮保持禁用；重新打开形象页面后，核对当前形象再继续。首页的单图和素材包导入也执行同一检查；当前窗口连续选择文件仍按最新选择保存，不会把另一窗口的更改当作自己的写入。

图片适配器向 `/images/edits` 发送 multipart 请求，要求 `data[0].b64_json` 返回 PNG。高保真与透明背景参数仅在服务支持时开启。等待时可“停止等待本次生成”；失败、停止、超时均不自动重试，也不保证服务未处理或未计费。本机适配器尚未结束时继续阻止重复提交，期间不能恢复备份或加入另一位伴侣。

首页“备份与调用”保留最近 30 条服务调用，底层最多保存 500 条。图片记录只有动作、模型、服务域名和状态，不保存图片、提示词或密钥；刷新和应用重启后仍在，进程中断的未完成记录转为结果未知。记录不进入加密备份或同步；每日尝试计数保存在本机使用量中，随原有备份规则保留。0.22.0 及更早版本无法读取包含新图片调用类型的本机数据库，使用该资料库前应升级应用。

本机背景处理只移除与画面边缘连通、颜色接近的背景，保留封闭区域里的同色细节；它不识别人像。浅色衣服或头发与背景相连时可能被误处理，必须先检查预览。已有透明轮廓会保守保留，复杂或过度清除的结果不能整组采用。原始素材字节保持不变，背景显示设置随保存、素材包、加密备份和同步保留；打开时由设备重新处理。任一可读取帧处理失败时，整组显示原素材并提示，实验台暂停生成，恢复原背景或重新打开重试后继续。

启用透明显示后，生成请求使用已预览的透明参考图；服务返回的动作仍保留适配后、采用所选位置的原始素材，以便恢复背景。预览、采用和恢复不产生服务请求，生成动作继续逐次确认。较早版本不应用这项显示设置，可能显示原背景，且重新保存后可能丢失设置；使用该功能的设备应统一升级。

首页与实验台的单图导入都会执行基础像素检查：拦截几乎全透明或纯色的画面，对短边小于 256 像素、低对比度、内容占比较小或透明内容贴边给出提示。PNG 素材还会在本机服务校验文件头与尺寸，超过 2000 万像素不上传或采用。0.20.0 另在本机 Worker 运行固定 MIT animeface LBP 分类器：检测到多张二次元脸时阻止新单图导入或采用新生成图，未检出、脸部过小或检查失败时明确提示。该检查不上传图片，也不证明人物数量、无遮挡、真实清晰度或身份一致性。模型来源和边界见 [图片原型说明](docs/avatar-prototype.md)。

0.12.0 修复了透明动作图叠在原图上时留下旧轮廓的问题。主窗口、小窗和实验台共用透明度混合，完整表情或闭眼帧会替换原轮廓，过渡期间保留透明边缘和半透明细节；返回待机时恢复原图。原有素材无需重新生成，日常播放不增加模型请求。实验台隐藏后停止逐帧绘制，返回后恢复；系统减少动态效果仍使用静态画面。

新生成素材会先等比适配，再通过本机 Worker 比较轮廓，尝试小幅平移和统一缩放。只有相关性与改善幅度达到门槛才提供对齐建议；结果仍由用户采用。大幅姿态改变、旋转、局部形变与更换人物无法据此修复。对齐、切换预览和叠加对照都不增加服务请求，坏图或比较失败保留已有素材。更换参考图会使旧的生成确认失效。

呼吸目前使用整体缩放，眨眼使用接受的闭眼图片交叉淡入淡出；不是骨骼绑定。真实模型的脸型、衣服、画风与位置一致性仍需要参考图与服务实测。

主窗口和伴侣小窗现在可以随回复播放已采用的微笑、疑惑和害羞素材。模型在同一次聊天或主动问候中附带表情名，应用分离正文和表情；不为表情额外请求模型，也不向对话服务发送形象图片。只在已准备表情素材时加入选择说明，未返回有效名称或缺少素材时使用原图。只有标记而没有正文的回复显示失败，不自动重试。

每次表情从回复完成起最多显示八秒，之后回到待机；不会因定时刷新延长或在重启后重放过期表情。播放非原始表情时不混入原图闭眼帧。替换形象、删除对应消息或出现相关同步冲突时使用原图；系统开启“减少动态效果”时关闭缩放、眨眼和淡入淡出，仍显示静态表情并按时回到原图。各模型遵守表情标记的表现及实际视觉质量仍需实测。

主窗口与小窗通过经过会话令牌验证的本机状态通知及时刷新，断开后重连并保留定时刷新作为补充。通知只表示资料已变化，不包含聊天、形象或密钥，也不会触发额外模型调用。

实验台中的编辑过程暂存在页面内存；离开前应“保存到伴侣”或导出。实验台素材包是未加密 JSON，只包含形象；它不等同于下面的完整加密备份。

## 加密备份与恢复

在设置“备份与调用”输入至少 10 个字符的口令，导出 `.niria` 文件。备份使用 scrypt 派生密钥与 AES-256-GCM 认证加密，包含身份、聊天、记忆、删除标记、保存的形象和同步版本关系，不包含服务连接、同步解密密钥或模型密钥。

0.17.0 修正了刚创建同步配对后立即导出备份可能无法恢复的问题。配对现在先完整保存当前同步版本图，再交付配对码，不需要再发消息或等待同步才能备份。

恢复前先保留当前备份，再填写口令并选择备份文件。恢复会替换本机资料；本机已有的删除标记仍优先，防止旧备份复活遗忘内容。全新设备用原口令恢复后仍需重新配置服务。

当前本机 SQLite 数据库未加密。导出的备份已加密，不代表本地磁盘、旧备份或其他设备的副本已被擦除。口令和所有备份均丢失后没有托管恢复服务。

## 多端加密同步

设置“多端同步”独立配置 WebDAV 文件夹地址、账号和应用专用密码。Nextcloud 的地址通常包含 `/remote.php/dav/files/账号/`；请提供已存在、允许创建子文件夹的目录。NIRIA 会在其中创建随机命名的专用空间，不覆盖其他文件。

首台设备点击“创建空间”，安全保管显示的配对码，再检查服务能力并“立即同步”。在另一台空白设备配置同一个 WebDAV 地址，输入配对码，点击“新设备加入并恢复”。已拥有同一身份的设备重启后，配置连接并用配对码“解锁”即可。

配对码包含随机的 256 位同步密钥与空间身份，持有它并能访问远端文件的人可以解密资料。配对码只会在你主动创建、显示或准备换钥时返回；普通伴侣数据库、备份、状态与调用日志不保存密钥。可单独选择在此电脑通过系统加密记住配对码，否则退出后需要重新解锁。“锁定并断开”会清除内存中的同步连接与密钥，并删除保存的配对码。恢复加密备份同样保持锁定。

采用 AES-256-GCM 加密后再上传。服务必须通过实际读写、强 ETag、`If-Match` 和 `If-None-Match` 检查，忽略条件写入的服务会被拒绝。测试产生的随机临时对象会尝试清理；清理失败时仅可能遗留测试对象，不会删除整个目录。

新增记录按稳定 ID 合并。并发修改人格、记忆、消息或形象时，双方版本保留在“多端同步”中供选择；有冲突的人格会暂停新对话，有冲突的记忆与消息不进入上下文。选定的版本在下次同步传播。删除标记优先于任何旧版本；遗忘也阻止离线设备用同源旧消息新增衍生记忆。

“允许发送模型”和“允许同步”分别生效。禁止同步的记忆及其来源、关联回复不上传；已上传后撤回权限会在下一次成功同步从当前远端正文撤除，其他设备已保留的本地副本与服务端历史备份不保证擦除。

同步默认手动，解锁后可选择每五分钟自动检查。记住 WebDAV 连接、配对码及自动检查选项时，重启后按已保存设置继续。失败先保留本机资料，不进行紧密重试。当前使用一个受条件更新保护的加密状态对象，包含版本图与已采用的形象，每次上传整个状态，大小上限 100 MB；尚未分块、压缩或做独立的资产增量同步。

“更换同步密钥”先在本机准备新配对码，暂停自动同步，并要求保存包含新旧配对码的换钥恢复文件。文件不含聊天或 WebDAV 密码，但两个配对码本身都是秘密，文件未加密，应离线保管。确认文件已保存后，点击“确认更换远端密钥”，应用读取、合并并有条件地重写当前加密文件。不会另建伴侣或丢弃版本图与遗忘标记。其他已有设备配置同一服务，输入新码“解锁”，再同步可保留离线新增的消息。

换钥过程中若网络中断、主动停止或本地提交失败，应用保留不含密钥的待核对标记，并停止上传。重新打开后，配置原 WebDAV 地址，在“只读核对换钥结果”先尝试新码；不能解密时再用恢复文件中的原码核对。核对只读取远端，成功后采用能验证当前文件的配对码；不自动重发换钥。自动同步保持暂停，可在确认其他设备更新后手动开启。本机安全保存配对码失败会单独提示，不能据此判断远端换钥失败。

所有设备目前共享配对码，换钥会影响所有其他设备，尚无按设备发放密钥或单独撤销某设备的协议。若设备丢失，还需在 WebDAV 服务端撤销对应的登录凭据；拥有写权限的旧设备仍可能破坏当前文件。换钥不删除该设备已保存的内容、旧配对码能解开的历史密文或服务端备份。

目前已验证本机 WebDAV 测试服务器，**Nextcloud 兼容性仍未实测**。详细协议和限制见 [同步设计](docs/sync.md)。

## 独立朗读

在“朗读”配置单独的 API 根地址、模型、声音名称及密钥。适配 `/audio/speech`，只发送所选回复文本并要求 WAV 输出；最长 4096 字符，音频最大 24 MB。支持该接口不代表任何服务都支持你填写的声音或模型，需单独测试。

自动朗读默认关闭；开启后，界面收到的新回复会尝试朗读一次。页面初次载入或恢复伙伴/备份的历史不会自动朗读。也可以点击回复下方“朗读（1 次请求）”手动播放。试听、自动和手动请求均计入每日上限，失败不重试，源回复删除或变化后丢弃过时结果。浏览器限制自动播放时可用音频控件手动播放。

等待音频期间显示“停止等待朗读”；停止、离开页面或来源变化会中断本机请求，迟到和已缓冲的旧音频都不会播放。停止等待仍可能已计费，调用结果按未知记录；已有音频可“停止朗读”并释放。音频只在当前页面内存和播放器中使用，不写入资料库、备份或同步。播放器明确标识为合成声音。

朗读请求先保存本机调用记录及使用量，写入失败不会向服务提交请求，也不会卡住后续朗读。结果状态保存失败时报告不确定，文字继续保留；停止、超时和服务失败均无自动重试。朗读状态不阻止独立的文字聊天。

## 验证与打包

```powershell
npm run check
npm test
npm run test:browser
npm run test:companion
node scripts/browser-smoke.mjs --avatar-safety
node scripts/browser-smoke.mjs --image-calls
node scripts/browser-smoke.mjs --speech-safety
node scripts/browser-smoke.mjs --chat-faults
node scripts/browser-smoke.mjs --sync-safety
node scripts/browser-smoke.mjs --backup-safety
node scripts/browser-smoke.mjs --credential-safety
npm run test:desktop
npm run dist:win
npm run test:packaged
npm run test:storage
npm run test:recall
npm run test:sync-storage
node scripts/desktop-smoke.mjs --packaged --upgrade --upgrade-v2
node scripts/verify-package.mjs
```

自动化接口与浏览器测试使用本机替身服务，不调用真实模型。浏览器使用隔离的 Edge / Chromium 资料目录；桌面测试使用独立资料目录并自动退出。截图与测试资料写入忽略提交的 `artifacts/`。

Windows 打包需要开发依赖和 Electron / NSIS 工具，首次可能下载。`dist:win` 只生成本地安装包，不发布。

已有完整本机缓存时，可运行 `node scripts/build-offline.mjs` 离线构建。该入口固定适配当前 Electron 45.3.1 / electron-builder 26.18.0，先核对四个缓存压缩包的 SHA-256，再将工具解压到 `artifacts/`；缓存缺失或校验失败即停止，不下载。可用 `--electron-zip <路径>` 和 `--builder-cache <目录>` 指定已有文件。构建时运行 NSIS 的原生 `BUILD_UNINSTALLER` 辅助程序，将工作目录限制在 `artifacts/`，仅生成卸载器；保存副本并核对卸载器及最终安装器的 CRC。此前直接提取卸载器的方式会产生 CRC 不匹配，已停止使用。此实现依赖当前构建器内部 API，升级依赖需先复核。

`node scripts/verify-package.mjs` 检查版本、运行文件内容、完整归档文件集合和安装器 CRC，并输出安装包与应用归档的哈希；使用 `--directory <安装目录>` 时还核对已安装卸载器的 CRC 及其与原生构建输出的哈希。离线构建后，`node scripts/verify-installer-payload.mjs` 只提取并比较安装器中的 `app.asar`、`NIRIA.exe` 和两份运行时许可文件，不执行安装器。最新本机证据汇总为 `artifacts/release-0.28.json`，安装包旁附有 `.sha256` 文件；这些产物不进入仓库。

服务配置、接口要求、实际验证环境和待验证产品见 [配置与兼容清单](docs/compatibility.md)。安装器的只读预检可运行 `pwsh -NoProfile -File scripts/installer-smoke.ps1 -InspectOnly`。实际安装验收已于 2026 年 11 月 14 日获得用户授权并通过；测试注册、快捷方式、安装目录及临时哨兵均已清理，完整首版的真实服务与实体双设备验收仍待完成。
