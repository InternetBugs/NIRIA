# NIRIA 加密同步协议 v1

当前是 0.19.0 开发预览实现，远端协议仍为 v1。兼容目标为用户自选 WebDAV，首个待实测服务为 Nextcloud；本机测试服务器通过不代表真实 Nextcloud 已验证。本机实体表迁移、记忆分页、同步元数据拆分、发送范围核对与成功后替换回复不改变远端对象或配对码格式。

Live2D 资料结构沿用形象版本图。0.18.0 用结构夹具验证同步、图片/模型冲突与明确选择后的收敛；0.19.0 接入官方播放器，并新增真实 Haru 模型通过本机 HTTP WebDAV 加密恢复后播放的验证。0.17.0 及更早客户端不认识这种形象，0.18.0 没有官方播放器，使用 Live2D 的设备应升级到 0.19.0 或更新版本。远端 envelope 仍为 v1 不表示较早程序支持新形象。

## 文件与密钥

在用户指定的 WebDAV 目录下创建 `niria-<随机 vault UUID>/state.niria`。空间创建与查询只在用户配置后执行。文件内容是有版本号的 AES-256-GCM 信封，使用客户端随机生成的 32 字节密钥，12 字节随机 nonce，16 字节认证标签。

AAD 固定包含协议版本、空间 ID 与伴侣 ID。该绑定阻止把一个空间的有效密文复制成另一空间的资料。配对码格式 `NIRIA1.<Base64URL JSON>` 包含空间 ID、伴侣 ID 和密钥；**配对码是秘密，不是公开的设备编号**。服务器登录信息单独配置。密钥不进入普通伴侣 SQLite、备份、状态接口或模型请求。Windows 桌面版可以单独选择系统加密保存配对码，密文位于独立的本机配置文件。

服务器仍可看到对象名、文件大小、修改时间、访问频率和账号。服务器管理员可能保留历史文件版本或备份；撤回或遗忘不能保证擦掉这些副本。拥有有效配对码的设备属于同一信任域。新设备没有之前的检查点，不能识别服务端回放的旧但有效密文；已有设备保留的版本图与删除标记会防止旧资料覆盖本机新版本。

## 状态合并

状态包含单个伴侣身份、消息、记忆、已接受形象和删除标记；服务设置、凭据、主动关心频率、调用日志、每日配额与窗口位置留在设备。关系资料包含于人格和带来源的共同经历记忆，未增加故事系统。

每个同步实体保存修订有向无环图。历史节点只包含随机修订 ID 与父节点，不保存旧正文；当前叶节点保存需要合并的版本、设备 ID 与时间。顺序修改只留下最新正文，并发修改留下多个叶节点。祖先判定使用图关系，不能用本机时间或整数 revision 判断新旧。

收到的整份资料先验证结构、实体 ID、修订图无环、父节点存在及叶节点一致，再应用。消息来源除整数 revision 外还保存正文哈希，防止两个设备同时产生“修订 2”却内容不同时误用衍生记忆。

0.11.0 的记忆可携带 `supersededSources`，记录手动纠正前的来源版本与哈希。这些记录保留权限和遗忘关联，不是纠正内容的有效性依赖。所有已知冲突候选的纠正关联也参与上下文排除；从离线端同步来的旧来源衍生记忆停止引用。纠正记忆被删除后，删除标记仍保留必要的关联版本，空白新端不必收到已删记忆正文就能排除旧来源。原聊天不会只因记忆纠正被删除，原消息后来不同版本仍可使用。旧客户端不执行这些规则，应使用 0.11.0 或更高版本参与这项能力。

消息可以携带可选表情名称、素材摘要及发生时间；旧消息不含此字段仍有效。表情随加密资料传递，但收到已过期或素材不匹配的表情不会重放。消息显示通常按时间与稳定 ID 排序；同一毫秒或回复时钟回拨时，回复不排到其对应用户消息之前。这个显示顺序不参与修订新旧判定。

多个叶节点表示冲突，不默认选“时间更晚”的版本。人格冲突暂停新对话，消息与记忆冲突暂停引用。用户选择一个版本时，新修订以所有冲突叶节点为父节点，下次同步后两端收敛。形象冲突提供图片预览。

删除标记包含实体 ID、种类、时间与必要的来源 ID，不包含被遗忘正文。删除胜过任何修订分支。0.10.0 将本机、恢复与同步的传播统一：沿 `replyTo` 递归删除关联回复，显式遗忘会继续清除以这些来源或回复为依据的记忆。遍历不依赖记录顺序，普通删除不能降级遗忘，多个删除分支的来源 ID 按并集合并。合并时同时使用当前叶节点和本机保留的关系，包括此前已删除、未上传或禁止上传正文的本地记录；后者只贡献 ID 关系，不进入远端正文。

用户确认前先看到本机影响清单，相关变化会使旧计划失效；离线端尚未到达的相关记录在下次合并继续处理，不能在本机清单中提前列出。混合来源记忆会撤除，其独立的其他来源不因此自动遗忘。没有显式来源关系的独立资料不按文字相似性删除。当前不回收删除标记。

记忆隐私权限独立。撤回同步权限用空内容修订替代该记忆、其来源及关联回复的正文；另一端收到后保留本地已有副本并禁止再上传。显式重新允许可再次上传，但与未观察到撤回的离线分支相遇时，撤回优先，需先同步再明确重新允许。

## 并发与故障

写入新文件用 `If-None-Match: *`；更新已有文件用 GET 返回的强 ETag 加 `If-Match`。首次先创建唯一测试对象，确认错误 ETag 和重复创建真的被服务拒绝，再验证有效条件更新，而不是只相信 OPTIONS。

遇到 412 时重新读取并合并，最多四轮。精确的本机修订 ID 在上传前持久保存，处理 PUT 实际成功但响应丢失的情况；重启后重新解锁再同步不应产生自冲突。上传期间有本机编辑则重新观察本机原有分支，再合并，不能将编辑假装为未见过远端修改的后继。

本机状态与同步元数据保存在同一 SQLite 事务中。任务有超时、单任务互斥和主动停止；自动检查至少间隔五分钟。本机资料不会因为失败被回滚到旧的远端状态。未发生资料变化的同步不会无故停止正在进行的聊天。

0.17.0 创建配对时先观察当前完整资料，保存有效版本图与指纹后才返回配对码；失败时不留下半完成的配对。修正了此前创建配对后、尚未再次修改资料便导出备份可能缺少身份版本的问题。刚配对即可备份，无需先调用模型或上传；空白伴侣及已有消息/记忆均已验证加密导出与新设备恢复。

重新回复等待期间，原回复仍保留在本机和同步资料中，新请求单独排除原回复及其衍生记忆；失败不发布原回复的删除。成功时新回复完成、旧回复删除与衍生停用一次提交；旧备份及离线端继续遵守删除标记。该行为已用两个本机客户端及真实 HTTP WebDAV 测试服务器检查，实体设备验收仍待进行。

0.15.0 的本机存储版本 3 将 `sync_meta` 改为小型表头，修订正文、记录顺序、删除标记与指纹分别存表，未变化的行跳过写入。排序移动不会重写形象正文；撤权/遗忘时仍清理相关正文。所有表与伴侣状态一起提交或回滚，升级失败恢复原格式；旧版拒绝打开新库。该改动只减少本机逻辑写入，运行时仍加载完整修订图，WebDAV 仍读写整个加密对象。

## 换钥与中断核对

换钥保持空间 ID、伴侣 ID、文件路径、修订图与删除标记，生成新的随机 32 字节共享密钥。准备步骤只在内存生成新码，不访问远端，暂停自动同步并更新已保存的自动开关。用户先下载含新旧配对码的专用恢复文件，再明确确认；恢复文件未加密，不包含聊天和服务登录资料，必须按秘密保管。它不是完整伴侣备份。

执行前在本机持久保存待核对标记，包含随机操作 ID、原文件夹地址与新旧密钥的 SHA-256 标识，不保存密钥。标识绑定空间 ID 与伴侣 ID。远端仍采用原 v1 信封，不附带新密钥或密钥历史；用旧密钥读回、验证并合并当前状态后，以新密钥重新加密，用原 ETag 条件替换。412 最多重读四轮，避免覆盖同时发生的更新；普通同步与换钥互斥。上传期间的本机修改保持原分支并并入本机，未包含在此次上传中的内容留待后续同步。

旧的本机已存配对码在远端写入前移除，新码在成功后按独立保存选项用 Windows 系统加密写入。本机保存失败只显示独立警告，不将已完成的远端换钥报告为失败，也不自动重做。新码的外部恢复文件因此必须在执行前保存。自动同步保持关闭。

只要 PUT 可能已经发送，网络异常、主动停止或本地事务失败都保留待核对标记；重启、锁定或重新配置不能清除它。此时不允许普通上传、再次换钥或直接恢复备份，避免覆盖唯一的核对线索。只能连接同一原文件夹，用专用恢复文件的新码或旧码执行只读 GET；能解密并通过状态验证后，合并本机状态，在事务中采用对应密钥标识并清除待核对状态。核对失败继续保留；核对过程中不执行能力探测或任何写入。已在本机退役的旧密钥拒绝再次解锁，其他设备使用新码成功验证当前远端后也退役此前的密钥标识。

这一流程更换所有设备共享的密钥，没有设备级密钥封装或单设备撤销。失去信任的设备须同时在服务端撤销其登录凭据；客户端换钥不能撤销 WebDAV 的读写权限。旧设备已复制的数据、旧密文、备份和服务端历史版本不被擦除。未更新的旧客户端也可能依靠写权限破坏当前对象；新设备仍不能凭空识别服务器回放的历史。独立密码实现复核、实际 Nextcloud 的权限/历史版本行为与实体设备长期验收仍未完成。

## 备份

加密备份包含版本图与冲突资料，但不包含同步密钥。恢复后保持新的本机设备 ID，恢复版本关系，清除运行中的连接并锁定同步；用户重新配置 WebDAV 并用原配对码解锁。旧备份与本机删除标记冲突时，删除仍优先。

相同伴侣的旧备份不覆盖本机已经存在的纠正。若因此保留了本机纠正，同一空间对应记忆的已知版本关系也合入恢复图；恢复后重新观察实际资料，为变化建立正确后继，避免自身冲突或指纹误认为旧正文已上传。备份本身已有纠正时使用备份正文并合并原关联记录；原格式不变。此前旧客户端已丢失的纠正来源无法从新字段补回。
## 限制与后续验证

- 当前整个状态作为一个加密对象传输，包含 Base64 形象；没有资产分块或按记录增量上传。
- 传输上限 100 MB，单实体版本图和总节点数也设上限；达到时停止同步并保留本地，不静默丢记录。
- 本机伴侣资料和同步元数据未加密；远端对象与导出备份已加密。服务凭据与配对码默认仅在进程内存，可单独选择 Windows 系统加密保存；新设备仍需重新配置。
- 尚未完成 Nextcloud 实测、两台实体 Windows 长期运行、锁屏/休眠/网络切换、服务端历史版本策略与独立密码实现复核。

一手协议参考：Nextcloud Developer Manual 的 WebDAV Basic APIs，以及 RFC 4918（WebDAV）和 RFC 9110（HTTP 条件请求）。本实现不宣称所有 WebDAV 服务都满足条件写入要求。
