## 本机 Magpie 对话检查

2026 年 11 月 14 日按用户提出的本机 Magpie 方案，读取正在运行的网关，版本为 0.1.4174。网关在 `http://127.0.0.1:3425/v1` 提供 Chat Completions；本次读取模型列表及调用均未提供额外 API 密钥。此结果只适用于本机当前配置，不能据此认定其他 Magpie 实例也不需要认证。

本次使用 `auto/gpt-6.1-sol`，经 NIRIA 0.30.0 的生产 `CompanionService` 与 `complete` 提交共四次请求：一次连接测试、一次普通聊天、两次记忆整理。连接返回 `OK`，聊天返回有效中文。第一条来源明确写了“合成资料”，整理返回合法空数组，未达到原检查预期；该失败记录保留。将隔离来源改为普通事实陈述后，新一次整理返回两条待确认记忆，均保留当前用户消息的修订和哈希。没有自动重试，主动关心保持关闭；全部内容均为专门构造的测试资料。

确认这两条测试记忆后，另一个 Node 进程重新打开 SQLite，完整资料、伴侣身份和记忆摘要一致。原消息已移出最近 24 条上下文，仍可本地召回两条记忆。续验再向 `auto/gpt-5.6-sol` 提交一次请求，实际答出茶偏好和书店；预览与实际记忆引用一致，身份和记忆未改变，见 `artifacts/magpie-chat-acceptance-1794668570091/model-switch.json`。旧的四次请求汇总保留当时“尚未调用另一条路由”的状态，不将后续结果倒填为之前已通过。

原四次检查汇总为 `artifacts/magpie-chat-acceptance-1794668570091/result.json`；连接证据为 `artifacts/magpie-chat-smoke-1794668570091/result.json`。随后真实回复揭示旧引用可能绕过纠正/权限的缺口，已在源码 0.31.0 修复，再用 `auto/gpt-5.6-sol` 提交两次请求，分别确认纠正生效和撤权后旧事实不出现在请求及回复中；累计七次，全部为合成资料、没有自动重试。证据为 `artifacts/magpie-memory-context-0.31/` 的 `correction.json` 与 `permission.json`，未重建安装包。

模型名称、返回的模型标识及用量来自网关报告，未独立确认上游模型身份、实际计费、离线推理或长期体验。网关列出图片和朗读路径不代表这些能力已经验证；本轮未调用它们。

## 源码依赖安装范围

在干净源码目录执行 `npm ci`，按锁文件安装固定依赖，再执行 `npm run desktop`。当前锁文件已将 27 个 esbuild 包的下载地址统一为 npm 官方仓库，保留版本、完整性摘要和依赖关系；解决了本机 npm 12 默认策略拒绝跨仓库主机 tarball 的实际安装失败。应用运行文件和既有 0.30.0 安装包字节不变，包内容已重新核对。

2026 年 11 月 14 日在 Node.js 26.13.0、npm 12.2.2、Windows x64 上，将已有缓存中按锁文件摘要核验的包归入任务缓存，再用 `npm ci --offline` 新建副本自己的 `node_modules`。安装 285 个包，Electron 45.3.1、electron-builder 26.18.0 与 esbuild 0.28.2 均从副本解析；Electron 由其自身安装脚本解出已校验的缓存原包，esbuild 实际转换通过。

npm 12 的默认脚本策略跳过了 esbuild 与 electron-winstaller 的生命周期脚本；本轮保留该默认行为，验证范围不包含从这个新依赖目录构建安装包。安装和运行库准备期间的 Node 网络拒绝器拦截了一次 npm 自身版本检查，依赖来自缓存，没有外部下载；后续应用界面测试使用本机 HTTP 替身。此结果不等同于空缓存在线安装或其他 Node/npm 版本验证。汇总见 `artifacts/public-source-0.30.json`，依赖证据为 `artifacts/public-source-0.30-install.json`。

## 首次配置

1. 启动桌面版，打开设置填写对话 API 根地址、模型名称和密钥；先“应用连接”，需要验证时再“测试连接”。
2. 在“伴侣资料”填写名字、称呼和相处方式。发送第一条消息前，可用“发送范围”核对资料。
3. 图片服务在“形象”实验台单独配置；先导入原图，再逐个生成并采用闭眼和表情。图片生成每次都需要确认。
4. 需要朗读时配置独立的朗读服务并试听，再决定是否开启自动朗读。
5. 不使用同步也可在本机保存。需要同步时再配置 WebDAV，创建空间、保管配对码并检查服务能力。
6. 在“备份与调用”导出一次完整加密备份，并保管口令。新设备还需要自己的服务配置。

应用连接不会测试或调用模型。Windows 桌面版可分别选择安全记住服务配置及配对码；浏览器预览只在当前本机服务进程中使用密钥。关闭主窗口会退出桌面应用，主动关心随之停止。

0.28.0 遇到凭据库损坏、无法打开或读取失败时，会保留原文件并提示“已存配置尚无法核对或清除”。记住开关停用，但可以填写仅本次会话的连接；旧的已存配置并未因此清空，重启后仍可能生效。清除失败会返回错误；不要把无法读取的空列表当成已经清除。此降级不修复或替换损坏的伴侣资料库。

0.19.0 的“导入 Live2D”先选择完整模型文件夹、确认待机/表情映射，再本机预览和采用。官方播放组件与应用一同提供，不从 CDN 加载，也不调用生成服务。支持 Version 3 的 .model3.json + .moc3；旧 .model.json / .moc 不支持，具体资源预算、兼容边界和操作见 [Live2D 导入与播放](live2d.md)。

## 对话接口

填写 API 根地址，例如 `https://chat.example.com/v1`，不要包含 `/chat/completions`。远程服务须为 HTTPS，本机 `localhost`、`127.0.0.1` 或 `[::1]` 可使用 HTTP。模型名称使用服务实际提供的名称。

| 要求 | NIRIA 当前行为 |
| --- | --- |
| 路径 | 在根地址后添加 `/chat/completions` |
| 请求 | JSON：`model`、`messages`、`stream: false` |
| 消息 | `system`、`user`、`assistant` 的纯文本 `content` |
| 认证 | 填写密钥时使用 Bearer；本机免密服务可留空 |
| 响应 | `choices[0].message.content` 必须是非空文本，最长 16,000 字符 |
| 返回大小 | 整个响应最多 1 MB |
| 超时 | 一轮聊天及其自动整理共用 90 秒；失败不自动重试 |
| 未适配 | 仅支持其他请求路径、流式专用响应、工具调用专用结构或仅返回多段内容数组的接口 |

普通聊天一次请求。自动记忆开启时，成功聊天最多再整理一次，仅提交本轮用户消息，每日默认最多八次。主动关心默认关闭，有独立频率、免打扰和每日上限。连接测试也是真实请求，可能计费。

0.25.0 在服务调用前保存本机记录，初始落盘失败不会提交模型。停止和独立的适配器超时按结果未知记录；完成状态落盘失败明确提示不确定，不自动重试，也不覆盖原来可用的回复。正常聊天、重生成、主动关心和连接测试共用此处理，后台整理故障继续保留已完成文字。连接测试与聊天的 HTTP 响应断开只中断自己的调用；处理期间不能更换对话配置，恢复资料后拒绝旧结果。

切换模型会保留伴侣身份和本机记忆；模型自身是否遵守人格、事实和表情规则仍须实测。

## 图片编辑接口

图片生成在创建或重做素材时执行；日常播放已保存动作不请求图片服务。

| 要求 | NIRIA 当前行为 |
| --- | --- |
| 路径 | 在图片服务根地址后添加 `/images/edits` |
| 请求 | multipart，字段为 `model`、`n=1`、`image`、`prompt` |
| 参考图 | PNG 文件，最多 8 MB、2000 万像素；输入可由本机从 JPG/WebP 适配 |
| 响应 | `data[0].b64_json`，解码后必须为符合限制的 PNG |
| 返回大小 | JSON 响应最多 24 MB，PNG 本身最多 8 MB |
| 可选参数 | “高保真”添加 `input_fidelity=high`；“透明背景”添加 `background=transparent`，只在服务支持时启用 |
| 超时 | 180 秒；超时或失败不自动重复，服务仍可能已处理或计费 |
| 停止等待 | 中断本机上游请求，按结果未知记录；服务仍可能计费，迟到结果不交付 |
| 未适配 | 仅支持文字生图、仅返回图片 URL、需要先创建异步任务再轮询结果的接口 |

先生成一个动作确认兼容性，再决定是否继续。检查脸型、发型、服装、位置和画风，只有外观和切换效果可接受时才采用。一次生成失败保留原图及已有动作。

0.23.0 在首页“备份与调用”持久记录图片动作及处理中、已返回、失败、结果未知状态；已返回不代表素材已采用或通过外观检查。日志不包含图片、提示词、密钥或 API 私有路径，不进入备份或同步。旧应用不能打开含新图片调用类型的本机数据库；备份与同步 v1 协议未变化。

本机纯色背景处理不调用模型，仅处理与边缘连通的近似纯色；复杂背景的人物分割仍未实现。可用 [图像验收记录](avatar-prototype.md) 逐项检查真实素材。

## 朗读接口

| 要求 | NIRIA 当前行为 |
| --- | --- |
| 路径 | 在朗读根地址后添加 `/audio/speech` |
| 请求 | JSON：`model`、`voice`、`input`、`response_format: "wav"` |
| 文本 | 最长 4096 字符，只提交所选回复，不发送完整记忆和形象 |
| 响应 | WAV，包含 RIFF/WAVE 标识，最多 24 MB |
| 超时 | 60 秒；失败保留文字，不自动重试 |
| 停止 | 等待时可停止，离开页面也中断；停止/超时记录结果未知，仍可能计费，迟到音频不播放 |
| 调用上限 | 试听、手动与自动朗读均计入上限，默认每天 20 次 |
| 未适配 | 仅返回 MP3/Opus、音频下载 URL、WebSocket 或异步任务的接口 |

自动朗读默认关闭。服务模型和声音名称均由用户填写；接口成功仍需人工试听声音与效果。

0.24.0 会在请求前保存调用记录，初始写入失败不调用服务；完成状态写入失败报告结果不确定，释放忙碌状态。等待或播放期间的源回复变化、恢复备份或更换伴侣会作废旧音频。首次载入和恢复的历史不触发自动朗读，恢复同一身份也遵守此规则。文本聊天使用独立连接，朗读故障不妨碍继续聊天。

## WebDAV 与 Nextcloud

填写已经存在、具有读写权限的 WebDAV 文件夹地址。服务应支持集合操作、强 ETag、`If-Match` 和 `If-None-Match` 的实际条件检查；NIRIA 会用唯一测试对象验证这些操作，无法验证时停止同步。

Nextcloud 的 WebDAV 地址可从文件页面的设置中复制。建议创建应用专用密码；开启两步验证时，第三方 WebDAV 客户端需要使用这类凭据。设置入口和连接方式见 [Nextcloud 官方 WebDAV 说明](https://docs.nextcloud.com/server/stable/user_manual/en/files/access_webdav.html)。

可以先在 Nextcloud 文件中建立专用的 `NIRIA` 文件夹，再将它对应的 WebDAV 地址填入应用。格式示例：

```text
https://cloud.example.com/remote.php/dav/files/ACCOUNT/NIRIA/
```

`ACCOUNT` 应与实际 WebDAV 地址一致。不要填写公开分享链接、网页文件列表地址、仅供浏览器登录的页面，或在地址中内嵌密码。账号和应用专用密码分别填写。

首台设备依次执行“应用同步连接”“首台设备创建空间”“检查服务能力”“立即同步”。能力检查会创建文件夹并短暂写入一个测试对象，不调用聊天或图片模型。准备第二台空白设备时，填写其自己的 WebDAV 登录信息，再使用原配对码“新设备加入并恢复”。

0.26.0 在停止后拒绝迟到读取、能力和上传成功状态，保留本机资料；已经发出的写入仍可能在服务端完成，下次同步会重新核对。锁定立即清除会话密钥；若已存配对码的系统安全存储清除失败，会明确提示重启可能自动解锁。以上行为已用真实本机 HTTP 和受控延迟验证，不代表实际 Nextcloud 或实体双设备验收。

0.27.0 的备份恢复会核对确认后的资料与同步状态；读取文件或解密等待期间新增资料时，拒绝旧恢复并保留新资料。可停止尚未提交的操作；底层加密/解密结束前仍显示等待。恢复提交后无法通过停止撤销；若清除配对码或刷新页面失败，提示明确说明已经恢复。v1 备份文件继续支持；自行调用恢复 HTTP 接口时需先从当前状态获取 `backup.basis` 并作为 `expectedBasis` 提交。

同步对象是客户端加密的单个文件，当前上限 100 MB，形象素材包含在对象中。反向代理、存储配额及单文件限制需要允许该对象实际大小。应用不跟随重定向；使用服务最终的 HTTPS 地址。

Nextcloud 仍为待验收服务。2026 年 11 月 13 日的环境检查发现现有 Debian 内有 Docker 客户端，但无法连接 Docker daemon；没有启动或部署 Nextcloud，也没有据此添加真实兼容结论。

## 常见连接问题

| 现象 | 核对内容 |
| --- | --- |
| 应用连接成功，聊天仍失败 | 应用连接仅保存设置；检查模型权限、根地址和基础 Chat Completions 支持 |
| 文本服务可用，图片或朗读不可用 | 各项能力独立配置和验证；检查图片编辑及 WAV 接口 |
| 切换服务地址后提示重新填密钥 | 密钥不会跨地址复用；WebDAV 还绑定账号 |
| WebDAV 检查条件写入失败 | 服务或代理必须真正拒绝错误 ETag 和重复创建；NIRIA 不绕过该检查 |
| WebDAV 拒绝访问 | 核对文件夹地址、账号、应用专用密码与读写权限 |
| 等待超时 | 查看调用记录和服务控制台后再手动决定是否重试，避免重复计费 |
| 重启后需要重新填写连接 | 默认只在当前进程使用；Windows 需单独勾选记住配置，自动同步还需保管或保存配对码 |
