# NIRIA 图像原型验证

本阶段检验一张参考图能否生成可接受的动作目标，并由客户端播放。原型提供实际图片编辑接口桥接、逐次请求确认、人工采用动作、本机预览和素材包导入导出。

## 已实现

- PNG、JPG、WebP 单图导入，8 MB 和 2000 万像素限制，固定画布适配。
- 轻微呼吸预览，减少动态效果设置及页面不可见时停止动画。
- 为闭眼、微笑、疑惑、害羞分别提交一次图片编辑请求。
- 原图与生成结果对照，采用或放弃，已采用动作可单独重做。
- 原始表情下使用闭眼目标预览眨眼，其他表情可切回原始形象。
- 素材包导出及导入，服务配置与密钥不进入素材包。
- 本机会话检查、同源检查、重复请求阻止、请求超时及错误信息约束。
- 两个导入入口的空白/纯色拦截，以及原始分辨率、对比度、透明内容占比与贴边提示；本机服务解析 PNG 文件头并限制像素数量。
- 等比适配素材、Worker 内小幅平移与缩放建议、可取消的位置修正和原图叠加对照；采用时保存所选帧，保留其他动作。
- 实验台自动载入已保存伴侣形象，重开与再次保存不改写已有图像字节；换参考图使旧生成确认失效。
- 可恢复的本机纯色背景处理：逐张比较原图与所有已有动作，确认后采用；原图字节不变，保存、导出及加密备份/同步保留显示设置。
- 可读取帧中任一处理失败时整组显示原素材并提示，避免动画混用不同背景；恢复后解除生成限制，取消或晚到 Worker 结果不改写当前形象。
- 保存绑定当前伴侣和原形象，过时页面不能覆盖其他窗口、同步或恢复后的新资料；保存失败仍可导出编辑内容。
- 动作预览在检查期间即可关闭，取消后终止检查/位置比较 Worker，迟到结果不重新打开或采用。
- 图片请求先记录到本机，刷新/重启后仍可查看；等待可停止，未知结果可能已计费，迟到结果不交付。

## 图片调用记录与停止等待（0.23.0）

伴侣模式在上游请求开始前先持久保存处理中记录并增加每日图片尝试数，落盘失败不会调用服务。收到结果后标记已返回；服务失败标记失败；停止、超时和进程中断标记结果未知。记录已返回不代表图片已通过质量检查、被采用或保存为形象；放弃预览仍保留该次调用，旧形象不变。

实验台“本次调用”提供“停止等待本次生成”，离开页面也取消请求。取消后向本机图片适配器传递中断信号，迟到结果不再交付给页面；如果本机适配器忽略中断，仍保持串行锁直到该次调用结束，不自动重试。停止和超时不能撤回服务已经处理或计费的请求。图片请求和恢复备份/加入另一位伴侣互斥，防止本机调用记录被恢复操作抹除。

首页设置“备份与调用”展示最近 30 条记录，SQLite 最多保留 500 条，使用量保留最近 40 天。图片日志只保存动作、模型、服务 origin、时间和状态，不含参考图、结果图、提示词、密钥、私有 URL 路径或服务端异常正文。调用日志不进入备份和同步；原有每日使用量仍随完整备份保留。存储 schema 3、备份/同步 v1 不变，但旧应用无法读取含新图片调用种类的本机数据库。

`node scripts/browser-smoke.mjs --image-calls` 运行共享 `desktop/image-generation-smoke.mjs` 的 15 项检查，同组加入 Electron 源码回归。使用真实 loopback HTTP 与生产图片适配器，将合成像素交给回显、挂起或故障替身；验证停止后实际断开、未知记录、迟到拒绝、返回未采用、放弃保留记录、错误不泄密、首页中文标签、刷新恢复及恰好三次明确请求。独立的 16 项 Node 测试还覆盖身份替换、并发恢复互斥、日志写入故障、SQLite 重启及使用量/保留上限；这些测试不证明真实模型的质量或计费结果。

## 保存与取消（0.22.0）

首页单图与素材包导入、实验台“保存到伴侣”共同使用带前置条件的图片采用接口。请求必须包含图片素材 `avatar`、`identityId` 和 `expectedAvatarKey`（初始无形象为 null）；服务端检查当前身份和完整形象摘要，再在同一事务保存。未知或缺少依据返回 400，当前伴侣/形象已改变返回 409；均保留新资料。Live2D 必须经独立的真实模型预览和采用接口，不能由图片接口绕过。

成功保存后更新编辑依据，允许继续修改和保存。首页快速连续选择时，排队的新选择只接受本窗口刚完成且依据相符的写入；外部更改仍会拒绝旧选择。实验台发现过时时保留素材、显示持续提示并禁用保存，使用者可导出后重新打开；不会自动改用新版本覆盖。

关闭动作预览会取消人脸检查、背景处理及位置比较，释放对应 Worker。较晚的解码或 Worker 结果只能结束原任务，不能再次打开窗口或解锁旧的采用按钮；采用检查完成前禁用。检查失败、发送失败和取消不产生自动模型重试，已有动作继续保留。

`node scripts/browser-smoke.mjs --avatar-safety` 使用独立伴侣和合成图片检查保存后的依据推进、重复点击、外部更改拒绝、过时编辑可导出、关闭人脸/位置比较的迟到结果，以及 Worker 取消和发送失败清理。该专用模式不请求上游图片服务，其中一次生成返回由明确的页面内替身提供，不是实际图像模型质量验证；同一组检查也在 Electron 全套源码回归运行。Node 测试另覆盖真实 HTTP 的身份/摘要/来源认证、并发写入，以及回滚、SQLite 重启和加密备份。

## 本机二次元人脸检查（0.20.0）

新单图导入、实验台素材载入及生成结果检查使用固定的 animeface LBP 分类器。图像缩到最长边 640 像素，在一次性本机 Worker 中检查；不上传、不计费。多张人脸阻止新单图导入和新生成素材采用，实验台已有素材包可打开并提示，但原图阻断项解除前不允许生成。未检出人脸不能证明画面无人，只给出侧脸、遮挡、画风或脸部过小的提示；原图脸部短边小于 64 像素也会提示。

Worker 超过 8 秒终止；异常明确显示“未完成”，不当作成功。没有 Worker 时本机同步降级，模型请求仍有 8 秒超时，CPU 扫描有 640 像素和 1000 候选上限；同步扫描不能中途抢占。快速换图、关闭页面会取消旧检查；旧素材包读完后也不能覆盖新选择。检查失败或坏图不修改当前已采用形象，不额外请求生成。

来源为 nagadomi/lbpcascade_animeface 固定提交 `4433ab1ae1166ea75acfe99eb0f18709dac329a0`，MIT 许可保留在 `prototype/public/vendor/animeface/LICENSE.txt`，来源与哈希见 [第三方说明](../THIRD_PARTY_NOTICES.md)。分类器转换由 `scripts/vendor-animeface.py` 完成，无需运行时下载。

`node scripts/validate-animeface.mjs` 以独立 OpenCV 4.9.0 结果核对本机真实模型渲染的灰度测试材料；`node scripts/browser-smoke.mjs --faces` 验证 PNG 解码、RGBA、真实 Worker、失败与取消、无 Worker 降级、拒绝坏图保留原形象和旧素材包读取竞态。测试材料位于被忽略的 `artifacts/animeface-validation/`，不随仓库分发。Node 默认测试不依赖这些材料。

人脸个数不等于人数。此功能不能可靠判断身体、遮挡原因、清晰度、角色身份或生成表情是否自然，不能替代真实素材验收。

## 本机透明背景

在实验台点击“预览透明背景”，选择原图或已有动作查看前后差异，检查头发、衣服与边缘。全部素材可兼容且至少一张可处理时才可采用；采用后点击“保存到伴侣”，主窗口、小窗和重开的实验台按同一规则显示。“恢复原背景”保留所有原图和动作，保存后在其他窗口生效。处理完全在本机进行，没有图片模型请求。

处理只针对与边缘连通的近似纯色，不理解人物；封闭同色细节保留，与背景相连的浅色细节可能被误清除。已有透明轮廓保守保留；复杂背景、空白或过度清除阻止整组采用。任意可读取素材处理失败时整组恢复原素材显示，实验台提示并暂停生成；恢复背景或重新打开重试后再生成。

素材包 v1 新增可选 `background: { version: 1, mode: "edge-connected" }`，不存储处理后的替代图。开启时图片请求使用预览后的参考图；采用的动作保留等比适配及所选对齐的原始素材，显示设置在打开时重新处理。旧版本可能忽略或在保存时丢弃设置，多台设备使用该功能时应统一升级。

## 尚需真实素材验证

当前没有使用用户的参考图和图片服务凭据执行真实生成。接口替身测试只能证明请求与处理流程，不能证明模型会保持角色一致性或输出自然动画。

2026 年 11 月 14 日，用户选择将这项真实立绘与付费图片服务验收后移，先继续本地开发。下列条件仍保留为首版待办，不记为已验收。

选择一张有权使用、人物清晰且面部无遮挡的二次元单人立绘。记录使用的服务、模型名称、原图比例、生成参数及实际返回尺寸。每个动作分别记录：

| 检查项 | 通过条件 |
| --- | --- |
| 人物身份 | 脸型、发型、服装和画风保持可识别的一致性 |
| 画面位置 | 原图与动作图切换时，人物无明显平移、缩放或头部跳变 |
| 闭眼 | 双眼自然闭合，恢复到原图时无突兀闪烁 |
| 表情 | 微笑、疑惑、害羞可辨认，程度适合日常聊天 |
| 循环播放 | 呼吸与眨眼能连续播放，不产生明显的全画面跳动 |
| 独立重做 | 拒绝或重做一个动作不破坏其他已采用素材 |
| 服务失败 | 显示可理解状态，保留原图和已有素材，不自动重复请求 |
| 素材恢复 | 导出再导入后，原图和已采用动作完整，未携带密钥 |

生成图改变身份或明显偏移时，记录失败并放弃该素材。不能仅以接口返回成功作为通过。

## 原型限制

输入检查包含像素、尺寸和本机二次元人脸检测；人脸数量不等于人物数量，遮挡、真实清晰度或身份仍需人工判断。全图位置修正不能代替语义外观校验、前景分割或局部配准；较大姿态变化和旋转仍可能无法修复，实际阈值尚需真实生成素材验证。

播放器使用全帧交叉淡化和整体缩放。这是验证素材的基线，并非已完成的部位绑定或骨骼动画系统。图片服务的透明背景与高保真编辑参数是独立能力选项，默认不开启，是否可用需按模型实测；本机背景处理不依赖服务支持。

实验台素材包为未加密图片集合。完整应用已有独立的加密伴侣备份，包含保存的形象；聊天、长期记忆、朗读和 WebDAV 同步的当前状态见仓库首页。

## 自动检查

运行 `npm run check` 和 `npm test`。测试不调用真实模型，覆盖费用相关的单次请求约束、敏感错误信息保护、接口格式校验和本机服务访问边界。

背景处理新增 13 项自动测试，覆盖封闭细节、半透明边缘、底色污染、透明素材不重复处理、复杂/空白/过量移除回退、参数校验、原字节保留，以及 SQLite 重开、加密备份和 WebDAV 恢复显示设置。两种浏览器流程实际检查 Worker 像素、逐张预览、取消、采用、导出/导入和生成确认；伴侣模式另验证保存。共享异常流程注入真实 Worker 的发送失败，检查终止、三张素材一起回退、同一标识不重复处理、新标识恢复、迟到结果及没有 Worker 时的降级。

原生 Windows 检查两个窗口的透明/恢复像素，连续创建独立实验台验证保存后两次重开与恢复后再次重开，并核对原始字节及零新增模型调用。390px 预览截图为 `artifacts/prototype-background-mobile.png`。这些像素和素材均是明确的合成夹具，不代表真实立绘效果。

视觉验收需同时检查浏览器实页与真实生成素材；浏览器界面测试通过不等于图像质量通过。
